# Data layer reference

Full detail for `sec_edgar_data.py` and `quick_stock_metrics.py`, moved out of CLAUDE.md to keep the always-loaded file short. CLAUDE.md keeps the summary and the traps; read this file before editing either module, or when a statement number looks wrong.

## sec_edgar_data.py

- Used because Yahoo Finance is often stale for weeks after an earnings release; SEC EDGAR reflects numbers as soon as the 10-Q/10-K is filed and XBRL-tagged
- `fetch_edgar_statements(ticker)` — looks up the ticker's CIK, pulls the full company-facts payload, and saves JSON using the same Yahoo-style line-item names (`"Total Revenue"`, `"Operating Income"`, etc.) and file paths the old Yahoo statement fetchers used, so `chart_*.py` / `quick_stock_metrics.py` need no field-name changes
- **Tag selection is freshness-based, not first-match.** Each line item has a priority-ordered list of candidate XBRL tags (companies don't all use the same tag, and filers routinely retire a tag mid-history with no announcement — e.g. COHR switched `InterestExpense` → `InterestExpenseOperating`, LITE switched `RevenueFromContractWithCustomerExcludingAssessedTax` → `...IncludingAssessedTax` mid-FY). `_extract_tag_series()` evaluates every candidate tag and keeps whichever has the most recent data (tiebreak: more quarterly data points, then list order) — never assume "first tag in the list" is what actually gets used for a given ticker.
- **Discrete quarters are derived by grouping same-fiscal-year facts and diffing.** Many filers report cash flow (and sometimes income statement) facts as cumulative year-to-date in 10-Qs (a 6-month figure for Q2, 9-month for Q3) rather than discrete quarters, and never tag a standalone Q4 at all (only the 10-K full-year total). `_extract_tag_series()` groups all duration facts sharing the same period *start* date (= one fiscal year) and successive-diffs them by end date — this reconstructs clean discrete quarters regardless of whether the filer reported discrete, YTD-cumulative, or a mix, and Q4 always falls out as `FY total − 9mo YTD`.
- Derives line items a filer doesn't directly tag via backfill logic — see `_backfill_income_statement()` (Gross Profit, Cost Of Revenue when only Gross Profit is tagged, Operating Income, Operating Expense), `_backfill_balance_sheet()` (Total Debt, and Total Liabilities from the `Assets = Liabilities + Temporary Equity + Stockholders Equity` identity when a filer doesn't tag an aggregate `Liabilities` concept at all, e.g. Oracle), `_backfill_cash_flow()` (Free Cash Flow)
- **Some filers never tag certain concepts at all, so the field comes back `{}` or `0` rather than wrong — check before treating it as a real value.** This is distinct from the three mechanisms below (which handle tags that *change* or *go stale*); here the concept is simply absent from the company-facts payload for that filer, so no amount of tag selection recovers it. Observed cases: SWKS reports `Total Debt` as `0` for the latest quarter after retiring its 2026 notes (actual long-term debt ~$497M, available under `LongTermDebt`), and AKAM leaves `Total Debt`, `Long Term Debt`, PP&E and goodwill untagged entirely. A `0` or empty debt figure on a company you know carries debt is this, not deleveraging — fall back to `_quick_metrics.json` (Yahoo) or the 10-Q, and cite the fallback source in the output. Any leverage ratio computed from an untagged debt line (D/E, net debt/EBITDA) will be silently wrong, not obviously wrong.
- **A line item that a filer stopped tagging entirely (no successor tag anywhere) is dropped, not left stale.** `_drop_stale_line_items()` nulls out any non-anchor line item whose most recent tagged date trails the statement's own anchor line item (Total Revenue / Total Assets / Operating Cash Flow) by more than `STALE_LINE_ITEM_DAYS` (500) — e.g. Oracle hasn't tagged `CostOfRevenue`/`GrossProfit` since FY2018. This is distinct from the freshness-based tag *selection* in `_extract_tag_series()`, which only helps when a fresher candidate tag exists to switch to; here there may be none, so the field is cleared to `{}` rather than silently pairing a years-old figure with the current period's other line items. Applied separately to quarterly vs. annual per statement (a tag can be stale in one cadence but current in the other), via the `anchor_key` param threaded through `_build_duration_statement()` / `_build_instant_statement()`.
- Balance sheet also captures `"Temporary Equity"` (mezzanine/preferred stock, e.g. convertible preferred issued for an acquisition) since it sits between Liabilities and Stockholders Equity under GAAP — without it, `Assets - Liabilities - Stockholders Equity` will not reconcile to zero for filers carrying such an instrument (this is expected, not a bug, until conversion/redemption)
- Balance sheet also captures `"Shares Outstanding"` — from the `dei` (Document and Entity Information) XBRL namespace, not `us-gaap` like everything else this module reads, and in `"shares"` units rather than `"USD"` (see `_get_shares_outstanding()`). Used by `quick_stock_metrics.py` to compute Price/Sales from SEC EDGAR fundamentals (Market Cap = Price × Shares Outstanding) without needing Yahoo's `marketCap` field.
- TTM (`_best_ttm()`) anchors all line items to the same four end-dates (from a statement's primary line item, e.g. Total Revenue for income statement, Operating Cash Flow for cash flow) so ratios between line items always cover the same 12-month window; falls back to the latest annual period directly when it's more current than any available quarterly stitch (e.g. a filer that stops tagging discrete/YTD quarters entirely partway through a fiscal year, only annual 10-K facts)
- Requires a descriptive `User-Agent` with a contact email on every SEC request (see `USER_AGENT` constant)
- Can be run directly: `.venv/Scripts/python sec_edgar_data.py TICKER`
- When statement numbers look inconsistent (a metric stuck on a stale date, a reconciliation identity like Revenue − Cost = Gross Profit failing), the fix is almost always one of the three mechanisms above — check whether a tag got retired/switched, whether the filer reports cumulative YTD instead of discrete quarters, or whether the filer stopped tagging the concept entirely — before assuming it's a one-off ticker quirk

## quick_stock_metrics.py

- `compute_metrics(ticker)` sources statement-derived metrics (revenue, growth, margins, ROE, D/E, interest coverage, current ratio, FCF margin, Rule of 40, payout ratio) primarily from the SEC EDGAR JSON files (`_income_statement_ttm.json`, `_income_statement_annual.json`, `_balance_sheet_quarterly.json`, `_cash_flow_statement_ttm.json`), falling back to `_quick_metrics.json` only if the SEC-derived value is unavailable
- **Every metric is source-cited.** Call `compute_metrics(ticker, with_sources=True)` to get `(results, sources)` — a second dict, same keys as `results`, labeling each metric's *actual* source for that specific ticker: `SRC_SEC` ("SEC EDGAR"), `SRC_YAHOO` ("Yahoo Finance"), `SRC_HYBRID` ("Hybrid (SEC EDGAR + Yahoo Finance)"), `SRC_COMPUTED` ("Computed (Yahoo Finance price history)" — RSI), or `SRC_NA`. A metric's source can differ by ticker (whichever one's SEC-derived value happened to be unavailable falls back to Yahoo for that ticker only) — never assume a metric's source from its key name alone; read it from `sources`. Plain `compute_metrics(ticker)` (no second arg) still returns just `results`, unchanged, for backward compatibility.
- The Excel output cites sources two ways: ticker sheets get a visible 4th "Source" column; the Comparison sheet (which can't fit a per-ticker Source column without doubling width) puts the source in an Excel comment/hover-note on each value cell instead, plus a "Data Source Legend" section at the bottom explaining each label. Both ticker sheets and the Comparison sheet also carry hover-notes on every value cell (`_add_source_note()`) as the literal per-number footnote.
- Trailing P/E and Price/Sales are **hybrids**: the fundamentals (Diluted EPS TTM; Shares Outstanding from `sec_edgar_data.py`'s `"Shares Outstanding"` balance-sheet field) come from SEC EDGAR, but current price has no SEC EDGAR equivalent — SEC filings report historical financial statements, not trading prices — so `current_price` (Yahoo) is still required for both. Falls back to Yahoo's own `trailingPE`/`priceToSalesTrailing12Months` if the SEC-derived EPS or shares figure is unavailable, or if trailing EPS is ≤0 (matching Yahoo's own convention of not showing a trailing P/E for loss-making companies)
- Forward P/E and PEG have **no SEC EDGAR path at all** — both require forward-looking consensus analyst estimates (next-FY EPS, expected growth rate), and SEC filings only ever contain actual reported historicals, never estimates. Always sourced from Yahoo quote data.
- Remaining market-quote metrics with no SEC EDGAR equivalent (current price, 52-week range, market cap, dividend yield, sector) always source from `Outputs/{TICKER}/{ticker_lower}_quick_metrics.json` (via `load_quick()`)
- `debtToEquity` from Yahoo Finance is already expressed as a percentage (e.g. `173` = 173%); the script always divides by 100 to convert to a ratio — do not double-divide
- `dividendYield` from Yahoo Finance is already a decimal (e.g. `0.0052` = 0.52%) when read as `trailingAnnualDividendYield`, but `dividendYield` (the forward estimate field) is sometimes returned as a percentage — the script divides `dividendYield` by 100 to normalize; do not double-divide
- RSI is computed directly from `{ticker_lower}_price_history.json` (Wilder's 14-day method) inside `_calc_rsi()` — not sourced from Yahoo Finance
- Produces `Outputs/quick_stock_metrics_YYYYMMDD.xlsx` with per-ticker sheets + a `Comparison` sheet (placed first); `--summary SUMMARY.json` then adds a `Summary` sheet ahead of it (`write_summary_sheet()`, the `/quick_stock_metrics` screen read)
- Can be run directly: `.venv/Scripts/python quick_stock_metrics.py [TICKER ...]`
- `compute_metrics(ticker)`, `_short_comment(key, val, metrics)`, `METRICS`, and `color_current_price(metrics)` are imported by the `/single_stock_deep_research` skill's generated Word scripts — treat these as a shared library, not just a CLI script
- **The 22 `METRICS` keys are snake_case**, in render order: `current_price`, `week52_low`, `week52_high`, `rsi`, `market_cap`, `revenue`, `rev_growth`, `gross_margin`, `op_margin`, `ni_margin`, `roe`, `de`, `interest_cov`, `cur_ratio`, `fcf_margin`, `r40`, `trailing_pe`, `forward_pe`, `peg`, `price_to_sales`, `dividend_yield`, `payout_ratio`. Note there is no separate EV/EBITDA key (skills compute it from enterprise value and cite it in prose), `dividend_yield` returns `None` for non-payers while `payout_ratio` returns `0.0` for the same company, and ratio-style keys (`de`, `interest_cov`, `cur_ratio`, `peg`, `price_to_sales`) are plain multiples while margin-style keys are decimals needing `×100`. Iterate `METRICS` rather than hardcoding a key list, so a future metric addition flows through automatically.
- **A metric can be mathematically valid and still meaningless — read the label, not just the number.** `de` returns `-10.1x` for a company with negative book equity (e.g. SMG at −$208.7M), which `_short_comment` labels "Very conservative" because the arithmetic is below the 0.5 threshold. Similarly `roe` goes negative on negative equity without the company having lost money, and `trailing_pe` can diverge sharply from Yahoo's own figure when discontinued operations or impairments are in the TTM window. Sanity-check leverage and return metrics against the balance sheet's sign before repeating the label in a document.
